## Proposals for review

Not counted as tasks. Proposals the captain approved on 2026-10-03 are marked Implemented (or Partly implemented) with their commit and kept for traceability; the others still need sign-off.

- **PR-1 Mobile expanded player sheet. Implemented (`9e4ead0`, C-79, UI-6).** Rationale: loop, shuffle, volume and queue are hidden below `lg`, so mobile users cannot reach them (UI-6). Trade-offs: new surface and gestures versus keeping the bar minimal. Migration cost: about 2-3 days. Risks: overlaps safe-area and toaster offsets (UI-7); needs real-device testing.
- **PR-2 Upstream caching in `api()`. Implemented, not verified live (`cbb97f3`, C-71, PF-1).** Rationale: all routes are dynamic and upstream is cached only in-process for 60s. Add `next.revalidate` 60-600s or `use cache` in `packages/trpc/src/lib/api.ts` (PF-1). Trade-offs: speed and upstream load versus staleness. Cost: small to medium. Risks: cache key must exclude cookies; do not cache search or `user.*`; randomized endpoints must keep `cache: false` (C-24).
- **PR-3 `user.library` procedure.** Rationale: removes the `getUser` then playlists/favorites waterfall in `app/(root)/layout.tsx:19-29` (PF-2) with one aggregated call. Trade-offs: new aggregate versus granular procedures. Cost: small to medium. Risks: needs measurement first; larger payload per request.
- **PR-4 Bun catalogs. Implemented (`7adc277`, C-82).** Rationale: dedupe ranges for zod, drizzle-orm, bcryptjs, `@types/bun`, typescript, oxlint, oxfmt via root `workspaces.catalog` (DP-7). Trade-offs: single source versus extra indirection. Cost: small. Risks: needs bun >= 1.4 (CI pins 1.4.2) and Renovate must understand catalogs.
- **PR-5 CSP in report-only first. Report-only implemented (`88ea1e0`, C-81); enforcing remains (SE-10).** Rationale: no CSP exists (SE-10). Nonce via `proxy.ts` for the theme bootstrap and Umami; `img-src` from `IMAGE_CDN_HOSTS`; `media-src` for audio. Trade-offs: XSS hardening versus maintenance. Cost: medium. Risks: breaking playback or analytics; start report-only.
- **PR-6 Rate-limit auth endpoints.** Rationale: put `/api/auth` sign-in/up and `resetPassword` under a stricter Upstash bucket (SE-1, SE-4), after the throttle decision. Trade-offs: brute-force protection versus false positives. Cost: small to medium. Risks: shared-IP false positives; spoofable `x-forwarded-for` unless a trusted proxy is configured.
- **PR-7 Behavior tests with happy-dom. Partly implemented (`b05a907`, `516726d`, C-83); remainder in TC-1, TC-7.** Rationale: replace about 5 of the 18 source-string tests (slider-decode, song-list-decode, login-redirect, playerbar-favorite-state, queue-sheet) with `renderToString` rendering (TC-1). Trade-offs: real behavior coverage versus new test dependency. Cost: 1-2 days. Risks: happy-dom gaps with Base UI overlays; keep CSS-class guards as they are.
- **PR-8 Popover for the language picker. Implemented (`0390ef6`, C-97, UI-5).** Rationale: toggle controls inside menu items break menu semantics (UI-5). Trade-offs: correct semantics versus a different interaction. Cost: small (about 1 file plus a test). Risks: minor visual change.
- **PR-9 Token-based headings. Implemented (`928bb59`, C-73).** Rationale: replace gradient headings with `text-foreground` or a shared heading component (UI-3, UI-25). Trade-offs: contrast and forced-colors support versus a visible design change. Cost: small, about 15 places. Risks: needs design sign-off.
- **PR-10 Shortcuts toggle. Implemented with `Toggle` (`9e4ead0`, C-80), now a Switch (`0390ef6`, C-97).** Rationale: single-key shortcuts cannot be turned off (WCAG 2.1.4) (UI-26). A settings toggle (or modifier requirement). Trade-offs: compliance versus one more setting. Cost: small. Risks: persistence and discoverability.
- **PR-11 Shared `userMessage(error)` mapper.** Rationale: toasts showed raw tRPC messages (CD-3 landed as `lib/user-message.ts`; code mapping remains, CD-9). Trade-offs: friendlier copy versus lost detail. Cost: small. Risks: masking useful errors; keep logging.
- **PR-12 Per-endpoint cache TTL and `staleTime` policy.** Rationale: a per-endpoint TTL policy in `api()` (about 1h, low risk) and a per-query `staleTime` policy for imperative `utils.*.fetch`, because the global `Infinity` silently defeats `fetch` (PF-1, C-23). Trade-offs: freshness versus load; changing the default is app-wide. Cost: small to medium. Risks: regressions where code relies on the cached default.
- **PR-13 `shadcn` to devDependencies.** Rationale: (adopted, DP-5 done) build-time only and the only path bringing the `braces` advisory (DP-9). Trade-offs: cleaner production deps versus checking the `ui` script and CI. Cost: trivial (needs lockfile regeneration with bun 1.4.2). Risks: low.
- **PR-14 Shared `tests/helpers/env.ts`.** Rationale: one env snapshot/restore helper to prevent the leak class behind C-30. Trade-offs: shared helper versus per-test explicitness. Cost: small. Risks: low.
